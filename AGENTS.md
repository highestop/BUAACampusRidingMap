# BUAA Shahe Campus Map

Repository: `highestop/buaa-shahe-campus-map`.

## Required contribution and merge workflow

- Every independent modification after repository creation must have its own PR, including code, data, page copy, documentation, and project instructions.
- Process PRs strictly in sequence. Confirm the previous PR is merged before starting the next independent modification. Do not start subsequent changes, open subsequent PRs, or stack PRs while the previous one is unmerged.
- Reviewing and fixing the current PR belongs to the current task and may continue on its existing branch.
- Read-only analysis, status checks, and reviews may run in parallel, but must not modify files for the next independent task.
- Read the actual remote default branch name, synchronize it, and create each work branch from its latest state. Do not assume the default branch is named `main`.
- Make and verify the change, commit and push it, then create a PR. Never commit project updates directly to the default branch.
- Use **rebase merge**. Do not use squash merge or merge commits.
- The user has authorized this project's routine merges under this workflow. Automatically rebase-merge once applicable checks pass and no blocking review remains; do not ask for merge permission again for each routine PR.
- Do not bypass failing required checks, branch protection, or blocking reviews. Resolve the current PR's issues before proceeding.
- After merging, verify the PR is `MERGED`, remove its remote work branch, and synchronize the local default branch before starting the next modification.
- Queue new independent requests received before the current PR is complete. Finish the current PR first, unless the user explicitly cancels or replaces that work.

## Language

- Keep `README.md` in Chinese.
- Use English for other documentation, filenames, code comments, and descriptive technical metadata.
- Keep the user-facing page interface and original map/place names in Chinese, as explicitly requested by the user.

## Local viewer and data

- `route_network.html` is a self-contained offline viewer generated by `build_viewer.py`.
- It embeds `route_network.json` and `map_basemap.json`. Regenerate it when relevant content changes and verify the embedded data matches its sources.
- Synchronize local deliverables and bundles with the final merged version so project modifications do not remain outside Git.
- Keep intermediate correction screenshots, preview images, patch notes, and historical audit snapshots out of the repository. Retain current deliverables and current validation results.
- Preserve the OpenStreetMap attribution and license references.
